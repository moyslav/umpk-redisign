# ГБПОУ «Уфимский многопрофильный профессиональный колледж» — редизайн сайта

Современная, адаптивная и производительная версия официального сайта **ГБПОУ УМПК**
(Уфимский многопрофильный профессиональный колледж), реализованная на базе
**Next.js (App Router)**, **React 19** и **TypeScript**.

Проект переосмысляет прежний статический макет (`_archive/`) и превращает его в
полноценное серверное приложение с динамической маршрутизацией, централизованным
управлением контентом и фирменной дизайн-системой в стилистике Apple Human Interface
Guidelines (светлая и тёмная темы).

> ⚠️ Примечание о версиях: в проекте используется **Next.js 16.3.4** и **React 19.2.8**,
> которые содержат отличия от предыдущих мажорных версий. Прежде чем изменять код,
> сверяйтесь с документацией конкретной версии в `node_modules/next/dist/docs/`
> и с уведомлениями о деприкациях.

## Возможности

- **Главная страница** — hero-блок с CTA, быстрые ссылки, лента новостей, каталог
  направлений подготовки, преимущества, статистика и контакты.
- **Многоуровневое меню** — выпадающие панели для десктопа и полноэкранный
  выдвижной drawer для мобильных устройств.
- **Динамическая маршрутизация** — один роутер `[slug]` обслуживает категории,
  страницы-разделы, спецстраницы (новости, специальности, контакты) и prose-страницы.
- **Генерация статических страниц** (`generateStaticParams`) — все страницы
  собираются на этапе сборки.
- **Хлебные крошки**, заголовки страниц и уникальные мета-описания для каждого раздела.
- **Светлая и тёмная темы** с переключением, сохранением в `localStorage`
  и учётом системных настроек (`prefers-color-scheme`).
- **Кнопка «наверх» / skip-link** для доступности, семантическая вёрстка.
- **Полностью адаптивная сетка** и фирменные анимации (scroll-эффекты, градиенты).

## Как устроен контент

**Весь текстовый контент и структура сайта собраны в одном файле — `src/data/site.ts`.**
Здесь хранится практически всё: от телефонов и адреса до новостей и специальностей.
Для правок текстов не нужно трогать JSX-компоненты.

Основные экспорты:

| Экспорт | Назначение |
| --- | --- |
| `SITE` | Общие данные: название, адрес, телефоны, почта, соцсети, год основания |
| `MENU` | Структура главного меню — список категорий и их страниц |
| `CAT_INTRO` | Вводные описания («интро») для страниц категорий |
| `NEWS` | Массив новостей, показываемых на главной и на странице `/novosti` |
| `SPECIALTIES` | Список специальностей (код, название, квалификация, форма) |
| `PAGE_TEXT` | Тексты отдельных prose-страниц (абзацы + кнопки-ссылки) |

### Типы данных

```ts
type NavLink = { t: string; slug?: string; href?: string };
type Category = { label: string; slug: string; items: NavLink[] };
type Specialty = { code: string; name: string; short: string; level: string };
type NewsItem = { img?: string; date: string; title: string; text: string };
```

### Особенности контента

- Пункт меню может быть **внутренней страницей** (`slug`) либо **внешней ссылкой**
  (`href`) — например, расписание в облаке или платформа Moodle. Внешние ссылки
  автоматически открываются в новой вкладке с иконкой «внешний ресурс».
- В массиве `MENU` некоторые категории помечены `wide: true` — для них
  раскрывается более широкая панель меню (используется для больших разделов
  вроде «Студенту» или «Сведения об ОО»).
- `HERO_BADGES` — чипы в hero-блоке главной страницы (могут вести на страницу
  сайта либо на внешний ресурс).

## Как устроена маршрутизация

Сердце приложения — динамический роутер в `src/app/[slug]/page.tsx`.
Он перехватывает запросы вида `/<slug>` и решает, какой тип страницы показать:

1. **`/kontakty`** — выделенная страница контактов.
2. **`/specialnosti`** — выделенная страница со списком специальностей.
3. **`/novosti`** — выделенная лента новостей.
4. **Категория** (slug совпадает с `MENU[].slug`) — лендинг-страница категории
   со ссылками на все вложенные разделы.
5. **Известный раздел с текстом** (`PAGE_TEXT[slug]`) — prose-страница с абзацами
   и кнопками.
6. **Известный раздел без текста** — placeholder «Раздел в наполнении».
7. **Неизвестный slug** — страница `notFound()` (404).

Список допустимых `slug` формируется функцией `allSlugs()` на лету из `MENU`,
`PAGE_TEXT` и спецстраниц, а `generateStaticParams` собирает их в статические
HTML-файлы при сборке.

## Как добавить новую страницу

Новая страница добавляется **без создания файла** — достаточно правки данных:

1. **Добавить пункт в меню** — в нужную категорию внутри `MENU` (например,
   `{ t: "Моя страница", slug: "moya-stranica" }`).
2. **(Опционально) добавить текст** — блок в `PAGE_TEXT` с ключом `moya-stranica`,
   абзацами и кнопками-ссылками.
3. **(Опционально) добавить интро** — строку в `CAT_INTRO`, если это отдельная
   категория.
4. Если текст не добавлен, страница покажет аккуратный placeholder
   «Раздел в наполнении».

Чтобы страница была доступна по прямой ссылке и в меню, её `slug` достаточно
указать хотя бы в одном месте (`MENU` или `PAGE_TEXT`).

## Дизайн-система и темы

Дизайн-система реализована в `src/app/globals.css` на базе **CSS-переменных** и
подключённого Tailwind CSS 4.

### Токены

Все цвета, тени и градиенты описаны как переменные в `:root` (светлая тема)
и в `[data-theme="dark"]` (тёмная). Переключение происходит через атрибут
`data-theme` на элементе `<html>`.

Пример ключевых токенов:

```css
--bg: #f5f5f7;        /* фон страницы */
--surface: #ffffff;   /* поверхности (карточки) */
--ink: #1d1d1f;       /* основной текст */
--accent: #007aff;    /* акцентный синий */
--danger / --success / --warning;
--grad-hero / --grad-band / --grad-cta;
```

### Механизм смены темы

- В `<head>` вставляется инлайн-скрипт (`themeScript` в `layout.tsx`), который
  **до первой отрисовки** считывает тему из `localStorage` либо системных
  настроек и ставит атрибут `data-theme` — это устраняет «мигание» при загрузке.
- `ThemeToggle` переключает тему в рантайме и сохраняет выбор.
- Атрибут `meta[name="theme-color"]` синхронизируется с фоном текущей темы.

### Системный шрифт

Проект использует системные шрифты Apple (`-apple-system`, `SF Pro`, `Segoe UI`,
`Roboto` и т.д.), что гарантирует отличную производительность и родной вид
без загрузки шрифтовых файлов.

## Изображения и внешние домены

Изображения новостей загружаются с внешнего CDN и рендерятся компонентом
`next/image`. Разрешённые внешние хосты указываются в `next.config.ts`:

```ts
images: {
  remotePatterns: [{ protocol: "https", hostname: "m-files.cdn1.cc" }],
}
```

> Если вы добавите изображения с другого хоста, обязательно добавьте его сюда,
> иначе `next/image` не сможет их оптимизировать.

## Метаданные и SEO

Метаданные настраиваются в `src/app/layout.tsx` через `export const metadata`:

- **`metadataBase`** — сейчас стоит заглушка `https://umpk.example.ru`.
  **Обязательно замените на реальный домен** перед публикацией.
- **`title`** — шаблон: дефолтный заголовок и паттерн `%s — ГБПОУ УМПК`.
- **`description`** — общее описание сайта.

Для каждой динамической страницы метаданные генерируются функцией
`generateMetadata` в `[slug]/page.tsx` (берутся из `CAT_INTRO` или первого абзаца
`PAGE_TEXT`).

## Запуск в продакшене

1. Соберите приложение:
   ```bash
   npm run build
   ```
2. Запустите продакшен-сервер:
   ```bash
   npm run start
   ```

Приложение можно развернуть на **Vercel** (самый простой способ) либо на любом
Node.js-хостинге. Конфигурация Next.js расположена в `next.config.ts`, файл
настроек линтера — `eslint.config.mjs`.

## Полезные заметки

- Перед коммитом рекомендуется проверять код: `npm run lint`.
- Динамические страницы пересоздаются при каждом изменении `src/data/site.ts`.
- Архив предыдущего статического макета лежит в `_archive/` и не используется
  в рантайме — это исторический материал для справки.
- Ресурсы сборки (`/.next/`) и зависимости (`/node_modules/`) исключены из
  репозитория через `.gitignore`.
